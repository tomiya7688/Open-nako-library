# Open Nadeshiko Libraries

## 基本構想 v0.1

Open Nadeshiko Libraries は、日本語プログラミング言語「なでしこ」から、コンピューターが持つさまざまな機能を日本語だけで利用できるようにするためのオープンなライブラリプロジェクトです。

本プロジェクトの目的は、単になでしこ用ライブラリの数を増やすことではありません。

**プログラミングに存在する英語の壁をできる限り取り除き、「何をしたいか」を日本語でそのまま記述できる環境を作ること**を目標とします。

利用者が書くコードは、原則として日本語だけで完結します。

内部実装については、なでしこで書かれている必要はありません。既存の優れたソフトウェア、CLI、JavaScriptライブラリ、Go、Rust、C/C++、Pythonなどを積極的に利用し、それらを自然な日本語の概念としてなでしこから利用できる形にします。

---

## 1. 基本思想

### 「全部を日本語で書ける」を最優先する

Open Nadeshiko Libraries における最重要原則は、

> 利用者から見えるインターフェースを日本語だけで完結させる

ことです。

たとえば動画をエンコードする場合、利用者に以下のようなコマンドを書かせることは目的ではありません。

```sh
ffmpeg -i input.mp4 -c:v libx264 -crf 23 output.mp4
```

また、外部ツールの概念をそのまま露出させることも避けます。

理想的には次のように記述します。

```text
「入力.mp4」を「出力.mp4」にエンコード
```

詳細を指定する場合も日本語で記述します。

```text
設定は{
    映像形式:「H264」,
    音声形式:「AAC」,
    横幅:1920,
    縦幅:1080,
    品質:23
}

「入力.mp4」を設定で「出力.mp4」にエンコード
```

FFmpegはあくまで内部実装であり、利用者はFFmpegについて知る必要がありません。

---

## 2. 日本語化する範囲

日本語化の対象は、単なる命令名に限定しません。

以下を可能な限り日本語で提供します。

- 命令名
- 引数
- 設定項目
- 戻り値
- 定数
- エラー
- 警告
- ヘルプ
- 導入手順
- サンプルコード
- 設定ファイル
- ライブラリ説明

つまり、

**「コードだけ日本語、エラーになった瞬間に英語」**

という状態をできるだけ避けます。

たとえば内部のFFmpegが、

```text
Unknown encoder 'libx264'
```

を返した場合、そのまま利用者へ表示するのではなく、

```text
H264形式で映像をエンコードできません。
現在利用している動画処理環境では、H264エンコーダーを利用できません。
```

のようなエラーへ変換します。

必要であれば詳細情報として原文を確認できる仕組みを別途用意します。

---

## 3. 「実装」ではなく「概念」を提供する

Open Nadeshiko Librariesでは、特定製品や特定ライブラリをそのまま公開APIにしません。

たとえば、

```text
ffmpegライブラリ
```

ではなく、

```text
動画ライブラリ
```

を提供します。

同様に、

```text
ImageMagick → 画像
Tesseract → 文字認識
Pandoc → 文書変換
7-Zip → 圧縮
Git → バージョン管理
SQLite → データベース
```

という形で扱います。

これは、内部実装を将来交換できるようにするためでもあります。

たとえば動画ライブラリの内部実装をFFmpegから別のエンジンへ変更しても、

```text
「入力.mp4」を「出力.mp4」にエンコード
```

というなでしこコードは変更しなくてよい設計を目指します。

---

## 4. なでしこの役割

Open Nadeshiko Librariesでは、なでしこ自身ですべての処理を実装することを目標としません。

なでしこは、

**「コンピューターに何をさせるかを日本語で記述する層」**

として扱います。

重い処理や専門的な処理は、その分野ですでに成熟している実装へ委譲します。

```text
日本語のなでしこコード
        ↓
Open Nadeshiko Libraries
        ↓
共通実行基盤
        ↓
既存ライブラリ / CLI / ネイティブコード
```

たとえば、

```text
画像から文字認識
```

という命令の内部でTesseractや別のOCRエンジンが動いていても構いません。

```text
動画をエンコード
```

という命令の内部でFFmpegが動いていても構いません。

```text
音声を文字起こし
```

という命令の内部でPythonやネイティブAIモデルが動いていても構いません。

重要なのは、**利用者が内部実装を知らなくても使えること**です。

---

## 5. 共通実行基盤

個別ライブラリを大量に作る前に、外部機能をなでしこへ接続するための共通基盤を整備します。

### 5.1 サブプロセス

外部プログラムを安全に実行できる仕組みを提供します。

必要な機能として以下を想定します。

```text
プログラム実行
標準入力送信
標準出力取得
標準エラー取得
終了コード取得
実行時間制限
プロセス停止
常駐プロセス
```

ただし、この低レベルAPIを一般利用者が直接使うことを前提とはしません。

主にOpen Nadeshiko Libraries内部の基盤として利用します。

### 5.2 構造化通信

外部プログラムとの通信には、可能な限り構造化データを利用します。

基本形式としてJSONを第一候補とします。

```text
なでしこ
   ↓
JSON
   ↓
外部プログラム
   ↓
JSON
   ↓
なでしこ
```

外部実装は、

「JSONを受け取り、処理し、JSONを返す」

だけで、なでしこ用ライブラリのバックエンドとして利用できることを目指します。

これにより、ライブラリ開発者はなでしこ本体の内部構造を深く理解していなくても拡張機能を作成できます。

---

## 6. 外部実装と言語

バックエンドの実装言語は限定しません。

用途に応じて最適な実装を利用します。

```text
JavaScript / TypeScript
Go
Rust
C
C++
Python
既存CLI
WebAssembly
その他
```

利用者から見れば、どの言語で実装されているかは原則として関係ありません。

たとえばRustで実装された画像処理ライブラリであっても、

```text
画像を横幅800に縮小
```

と書ければ、それはOpen Nadeshiko Librariesにおいて十分になでしこのライブラリです。

---

## 7. 環境構築を利用者へ要求しない

Open Nadeshiko Librariesでは、

```sh
npm install ...
pip install ...
cargo install ...
apt install ...
```

などの環境構築を、可能な限り利用者へ要求しません。

理想的には、

```text
！「動画」を取り込む
```

だけで使用できる状態を目指します。

必要な外部実行ファイルや依存関係が存在しない場合は、Open Nadeshiko側が取得または案内します。

将来的には、

```text
ライブラリを取り込む
↓
依存関係を確認
↓
必要な実行ファイルを取得
↓
検証
↓
実行可能
```

まで自動化します。

---

## 8. ライブラリマニフェスト

外部バックエンドを統一的に扱うため、各ライブラリには機械可読なマニフェストを持たせることを検討します。

概念例：

```text
名前: 動画
説明: 動画と音声を処理する
実行方式: サブプロセス
内部実装: FFmpeg

対応環境:
    - Windows
    - macOS
    - Linux

依存:
    - ffmpeg

自動取得: 可能
通信形式: JSON
```

実際のファイル形式については、JSON、TOML、YAML等から別途検討します。

マニフェストによって、

- 対応OS判定
- 必要な依存関係
- バージョン確認
- ダウンロード
- 実行方法
- 権限
- ライセンス
- 更新

などを共通処理できるようにします。

---

## 9. ライブラリAPIの設計原則

命令は外部ソフトウェアの専門用語をそのまま翻訳するのではなく、日本語として自然な「やりたいこと」を表現します。

たとえば動画ライブラリなら、

```text
動画をエンコード
動画を変換
動画を切り抜く
動画を結合
動画から音声を取り出す
動画から画像を取り出す
動画の長さを取得
動画の情報を取得
```

のようにします。

可能な限り、

```text
FFmpeg実行
Codec指定
CRF設定
FilterComplex設定
```

のような内部実装由来の命令は公開しません。

高度な利用者向けに低レベルAPIを提供する場合でも、基本APIとは分離します。

---

## 10. 既存のなでしこ資産との関係

Open Nadeshiko Librariesは、既存のなでしこ標準命令や公式プラグイン、有志ライブラリを置き換えることを目的としません。

すでに十分な機能が存在する場合は、それを利用します。

新規実装の前に、

```text
なでしこ標準機能
↓
公式プラグイン
↓
有志ライブラリ
↓
既存の外部ソフトウェア
↓
Open Nadeshikoで新規実装
```

の順で確認します。

Open Nadeshiko Librariesは、**既存エコシステムに不足している部分を埋めるプロジェクト**として位置付けます。

## 12. 最初に作るもの

Open Nadeshiko Librariesの最初の成果物として、個別の大型ライブラリよりも共通基盤を優先します。

第一段階では、

1. サブプロセス実行基盤
2. 標準入出力通信
3. JSONベースの外部プログラム通信
4. 外部プログラムの存在確認
5. バージョン確認
6. 依存物の取得・管理
7. 共通エラー形式
8. ライブラリマニフェスト

を整備します。

その上で、この基盤の実証用ライブラリとして、外部ツールとの連携効果が分かりやすい「動画」などを実装します。

---

## 13. プロジェクトの目標

Open Nadeshiko Librariesが最終的に目指すのは、

**英語のライブラリを日本語へ翻訳することではありません。**

ユーザーがコンピューターへ行わせたいことを、そのまま日本語で記述できる環境を作ることです。

内部で何が動いているかを知らなくても、

```text
動画をエンコード
画像から文字認識
文書をPDFに変換
音声を文字起こし
データを保存
AIに質問
```

と書けば動く。

そして必要であれば、その裏側では世界中ですでに開発されている高速で成熟したソフトウェアを利用します。

**日本語で書けることと、高性能な既存技術を利用することは両立できる。**

Open Nadeshiko Librariesは、その二つをつなぐためのプロジェクトです。
